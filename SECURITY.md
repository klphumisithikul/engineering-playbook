# Security Policy

## Supported Versions

| Version | Supported          |
|---------|---------------------|
| latest `main` | :white_check_mark: |
| older releases | :x: (upgrade to latest) |

Update this table once the project has tagged releases to track.

## Reporting a Vulnerability

**Do not open a public GitHub issue for security vulnerabilities.**

Instead, report it privately using one of:
- GitHub [Security Advisories](../../security/advisories/new) ("Report a
  vulnerability" on the Security tab) — preferred.
- Email: `<security-contact-email>` (replace with a real monitored alias).

Please include:
- A description of the vulnerability and its potential impact.
- Steps to reproduce or a proof of concept.
- Affected versions/commits, if known.

## What to Expect

- **Acknowledgment** within 2 business days.
- **Triage & severity assessment** within 5 business days.
- **Fix or mitigation plan** communicated once triaged; critical issues are
  prioritized for an out-of-band patch release.
- Credit in the release notes/advisory, if desired, once a fix ships.

Please give us a reasonable amount of time to address the issue before any
public disclosure.

## Scope

This policy covers code and configuration in this repository. It does not
cover third-party dependencies (report those upstream) or social-engineering
attacks against individual maintainers.
